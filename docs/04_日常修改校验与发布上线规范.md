# 日常修改校验与发布上线规范（GitHub + 橙色云 SOP）

> **适用范围**：面向站点维护者与后续接手本项目的所有 AI 会话。  
> **线上环境**：
> - **GitHub 公开仓库**：`https://github.com/seme321/jingyan-kaoyan`（默认分支 `main`）
> - **橙色云（Cloudflare Workers + Static Assets + D1）**：Worker 名称 `jingyan-kaoyan`，D1 数据库 `jingyan-guestbook`，线上访问地址 `https://jingyan.h0mura.de5.net`（Build Output 目录 `web/.cloudflare/output/v1/`，配置文件 `web/cloudflare.config.ts`）

---

## 一、改动分级速查表

每次改完代码、数据或文档后，先对照下表判断属于哪一类改动，避免遗漏步骤或做无用重传：

| 改动类型 | 典型变更文件 | 是否更新 `sw.js` 缓存号 | 是否跑 `validate_course.mjs` | 是否跑 `npm run build` | 是否推送 GitHub | 是否发版橙色云 |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: |
| **A 类 · 仅文档/脚本** | `docs/*`、`README.md`、`scripts/*` | 否 | 仅改生成脚本后建议跑 | 否 | **是** | **否** |
| **B 类 · 前端代码/样式/PWA** | `web/src/**`、`web/index.html`、`web/public/manifest.webmanifest` | **建议递增**（大改必升） | 否（无数据变更可跳过） | **是** | **是** | **是** |
| **C 类 · 题库/公告/题图/立绘** | `web/public/data/**`、`web/public/mascot/**` | **是（必升）** | **是（必须 0 错误）** | **是** | **是** | **是** |
| **D 类 · 部署配置改动** | `web/cloudflare.config.ts`、`web/package.json`、`.gitignore` | 否 | 否 | **是** + `--dry-run` | **是** | **是** |

> [!TIP]
> 如果一次提交同时改了前端与题库（B + C 类），统一按 **完整六步发版流水线** 执行即可；只有纯文档/脚本改动（A 类）才跳过前端构建与橙色云部署。

## 二、标准六步发版流水线（SOP）

> **核心顺序原则**：**先本地全量校验通过 → 再推 Git 留存可回滚版本 → 最后推送橙色云上线 → 线上回归抽检**。禁止把未通过校验的内容直接推上公网。

### 第 1 步：数据校验与 PWA 缓存同步（C 类必做，B 类按需）

1. **新增试卷或数据文件时同步预缓存清单**：
   - 编辑 `web/public/sw.js`，若新增了 `<year>.json` 或板块元信息（如 `courses.json` 注册了新板块的 `index.json` / `chapters.json` / `formulas.json`），必须将其相对路径加入 `PRECACHE_URLS`。
2. **递增 Service Worker 缓存版本号**：
   - 将 `web/public/sw.js` 第 1 行的 `const CACHE_NAME = 'jingyan-multi-vXX';` 递增 1（当前为 `'jingyan-multi-v21'`），确保老用户的 PWA 客户端能及时淘汰旧题库/旧页面缓存。
3. **运行全站门禁校验（必须在仓库根目录执行）**：

```powershell
node scripts/validate_course.mjs
```

- **硬性验收标准**：所有板块所有年份均显示 `[OK]`，末尾输出 `Total errors: 0`。

---

### 第 2 步：TypeScript 严格检查与生产打包（B / C / D 类必做）

进入 `web/` 目录执行构建：

```powershell
Set-Location web
npm run build
```

- 该命令依次执行 `cf workers types`、前端与 Worker 双端 `tsc --noEmit` 以及 `cf build`（`@cloudflare/vite-plugin`），最终产物输出至 `web/.cloudflare/output/v1/`。
- **硬性验收标准**：退出码必须为 `0`，无任何 TypeScript、Vite 或 Build Output 报错。
- 若有 UI 大改、新路由或 Worker API 修改，建议先运行 `npm run dev`（即 `cf dev`）在本地联调确认后再进入下一步。

---

### 第 3 步：隐私、安全与合规红线自检（推送 Git 前必查）

因为 GitHub 仓库与橙色云静态资源目录均为**全网公开可访问**，提交前必须在仓库根目录运行：

```powershell
git status -s
git diff --stat
```

逐项人工/AI 核对以下 5 条红线，任意一条不满足则立刻中止提交：

1. **严禁出现原始含水印真题与备份文件夹**：`.gitignore` 已屏蔽 `河海大学已整理真题/`、`扬州大学待处理数据/`、`河海大学已整理数据/`、`扬州大学已整理数据/`、`assets_src/handdrawn_backup/`、`assets_src/mascot_raw/`，确认它们从未被强制 `git add -f`。
2. **严禁提交构建缓存与工具临时目录**：确认未包含 `web/dist/`、`web/node_modules/`、`.cloudflare/`、`web/.cloudflare/`、`scratch/`（或零散测试输出图）。
3. **严禁泄露凭据与账号标识**：确认未提交 `.env*`、`.dev.vars*`（含 `web/.dev.vars` 中的 `ADMIN_TOKEN`）、Cloudflare API Token；**公开文件中不要硬编码 `accountId` / `zone_id`**（本地 `cf` 会从已登录配置读取）。
4. **严禁回退合规与署名边界**：首页标题保持指示性降权写法；`AboutPage.tsx` / `README.md` 保留大肥鱼 `CC BY-NC-SA 4.0` 外链与二创声明、`gemini.webp` 非商业 AI 插图声明、48 小时权利通知邮箱；`PracticePage` / `YearPage` / `MockPage` 保留 AI 解析显式标注；公开留言板接口（`web/worker/index.ts`）必须强制保持 `status = 'pending'` **先审后发**前置审核约束，严禁绕过审核直接公开写入。
5. **排查编码与误删**：使用 `git diff` 快速扫一眼核心文件，防止无意写入 UTF-8 乱码（例如 `package.json` 的 `description`）或误删原有注释。

---

### 第 4 步：Git 规范提交并推送 GitHub

确认 `git status -s` 与 `git diff` 干净后，使用精准路径 `git add`（推荐列出变更目录/文件，避免误把临时文件扫进暂存区），遵循语义化提交前缀：

- `feat:` 新增真题、板块或重要前端功能
- `fix:` 勘误修题、公式/配图修复、Bug 修复
- `style:` 样式微调或示意图重绘优化
- `docs:` 仅文档（`README.md` / `docs/*`）更新
- `chore:` 依赖、构建、部署配置与杂项整理

```powershell
# 示例：按具体变更文件暂存、提交并推送到 origin main
git add .gitignore web/public/ docs/
git commit -m "fix(hhu-814): 勘误 2025 Q12 解析并更新离线缓存版本"
git push origin main
```

- **硬性验收标准**：`git push` 成功且事后 `git status -s` 为空。

---

### 第 5 步：推送至橙色云（Cloudflare Workers + Static Assets + D1）

> [!IMPORTANT]
> 本项目使用官方 **`cf` CLI（`1.0.0-rc.2` 及以上）** 与 `web/cloudflare.config.ts` 进行全栈 Workers 部署。**严禁**安装 `wrangler` 或新增 `wrangler.jsonc` / `wrangler.toml`。

1. **检查登录态**：

```powershell
cf auth whoami
```

- 确认输出中 `"authenticated": true` 且账号邮箱为 `amassss321@gmail.com`。
- 若 OAuth Token 已过期，先执行 `cf auth login`，按终端提示在浏览器用 `amassss321@gmail.com` 确认授权。

2. **若新增或修改了 `web/migrations/*.sql`**：先检查或应用远程 D1 迁移：

```powershell
Set-Location web
npm run db:migrate:remote
```

3. **若改动了 `web/cloudflare.config.ts`（D 类）**：先空跑检查 Build Output 与配置语法：

```powershell
Set-Location web
npm run build
cf deploy --prebuilt --dry-run
```

4. **正式部署上线**：

```powershell
Set-Location web
# 日常更新（保留线上已有 ADMIN_TOKEN Secret）
npm run deploy

# 首次上线或需要轮换 web/.dev.vars 中的 ADMIN_TOKEN Secret 时：
npm run build
cf deploy --prebuilt --secrets-file .dev.vars
```

> `npm run deploy` 会自动串联 `npm run build && cf deploy --prebuilt`，将 `web/.cloudflare/output/v1/` 中的静态资源与 `worker/index.ts` 上传至 `jingyan-kaoyan` Worker，并自动同步自定义域名触发器 `jingyan.h0mura.de5.net`。

- **硬性验收标准**：终端输出 `Uploaded ... assets`、`Deployed jingyan-kaoyan triggers (jingyan.h0mura.de5.net)` 及 `Deploy complete`，退出码为 `0`。

---

### 第 6 步：线上回归抽检与文档同步

部署完成后，在 PowerShell 执行一次轻量化线上回归验证（注意 Windows PowerShell 5.1 下请用 `UTF8` `WebClient` 读网页文字，避免误判编码）：

```powershell
$wc = [System.Net.WebClient]::new()
$wc.Encoding = [System.Text.Encoding]::UTF8
$html = $wc.DownloadString('https://jingyan.h0mura.de5.net/')
Write-Output ("首页可访问且标题正确: " + ($html -match '鲸研专业课'))

foreach ($u in @(
  'https://jingyan.h0mura.de5.net/data/courses.json',
  'https://jingyan.h0mura.de5.net/sw.js',
  'https://jingyan.h0mura.de5.net/data/hhu-814/2025.json'
)) {
  $r = Invoke-WebRequest -Uri $u -UseBasicParsing -TimeoutSec 20
  Write-Output "$($r.StatusCode) | $($r.Headers['Content-Type']) | $($r.RawContentLength)B | $u"
}
```

- 若本次涉及“新增一整套真题、上线新专业课板块、架构或发版命令调整”，顺手更新 `docs/HANDOFF.md`（必要时同步 `README.md`）并补充一笔 `docs:` 提交推送到 `main`。

## 三、高频场景一键命令模板

### 场景 1：改了几道题 / 换了图 / 修了前端样式

```powershell
# 1. 若改了 data/ 或图片，先递增 web/public/sw.js 的 CACHE_NAME
# 2. 全站数据零错校验 + 前端生产构建
node scripts/validate_course.mjs
Set-Location web; npm run build; Set-Location ..

# 3. 安全自检后推 Git
git status -s
git add web/
git commit -m "fix: 描述本次修改内容"
git push origin main

# 4. 推橙色云并确认线上生效
Set-Location web; npm run deploy; Set-Location ..
```

### 场景 2：新增一整套真题或新板块上线

```powershell
# 1. 入库并生成索引/WebP（自动跑一次校验）
python scripts/ingest_exam.py --course <courseId> --json "<数据路径>/<year>.json" --figures "<数据路径>/figures"

# 2. 手动更新 web/public/sw.js（追加年份 JSON 至 PRECACHE_URLS 并递增 CACHE_NAME）
# 3. 再次全站校验 + 构建
node scripts/validate_course.mjs
Set-Location web; npm run build; Set-Location ..

# 4. 同步文档（docs/HANDOFF.md、README.md）并安全检查后推 GitHub
git status -s
git add web/public/ docs/ README.md scripts/
git commit -m "feat(<courseId>): 上线 <year> 年真题精解"
git push origin main

# 5. 发布到橙色云
Set-Location web; npm run deploy; Set-Location ..
```

### 场景 3：只改了说明文档或本地工具脚本（A 类）

```powershell
git status -s
git add docs/ README.md scripts/
git commit -m "docs: 更新说明文档"
git push origin main
# 无需构建，也无需运行 npm run deploy
```

### 场景 4：线上发现严重问题，紧急回滚

```powershell
# 1. Git 回滚最近一次错误提交（保留历史可追溯，勿强推覆写）
git revert HEAD --no-edit
git push origin main

# 2. 用回滚后的代码重新构建并覆盖橙色云线上版本
node scripts/validate_course.mjs
Set-Location web; npm run deploy; Set-Location ..
```

> 补充：如果本地来不及重新构建，也可以直接在终端运行 `cf workers deployments`（或登录 Cloudflare Dashboard → `Workers & Pages` → `jingyan-kaoyan` → `Deployments`），一键将线上流量回切到上一个正常 Version ID，事后再补 `git revert`。

## 四、常见踩坑与避坑清单

1. **改了真题 JSON 但线上访问还是旧内容**：
   - 原因：未递增 `web/public/sw.js` 中的 `CACHE_NAME`，导致 PWA Service Worker 继续优先返回本地旧缓存（即便橙色云已更新）。
   - 解法：只要改 `web/public/` 下的静态数据或重要资源，务必把 `CACHE_NAME` 编号 `+1`，重新 `npm run deploy`。
2. **`cf` 版本要求**：
   - 本项目依赖 **`cf@1.0.0-rc.2`（`cf@latest`）** 与 **`@cloudflare/vite-plugin@2.0.0-rc.3`** 驱动 `cloudflare.config.ts` 全栈 Build Output（`cf build` + `cf deploy --prebuilt`）。
   - 解法：在新电脑或重装环境时执行 `npm install --global cf@latest`，在 `web/` 下执行 `npm install` 即可恢复对应版本。
3. **看到 `EBADENGINE` 警告以为报错**：
   - 本机环境 Node `v24.13.1` 安装 `cf@1.0.0-rc.2` 时，npm 会提示 `Unsupported engine (required ^22.23.0 || ^24.22.0)`，这仅是次要引擎版本提示，实测可正常打包与部署，无需强行折腾降级/升级 Node。
4. **PowerShell 5.1 下校验线上中文标题误报 `False`**：
   - Windows 自带 PowerShell 5.1 的 `Invoke-WebRequest` 默认会按 ISO-8859-1 解码未声明 charset 的响应体。测汉字内容请用 `[System.Net.WebClient]` 并指定 `Encoding = [System.Text.Encoding]::UTF8`，或改用 `curl.exe`。
5. **公开文件禁止写死 Cloudflare `accountId`**：
   - 仓库 `seme321/jingyan-kaoyan` 为 Public 仓库，`web/cloudflare.config.ts` 中禁止添加 `accountId`；由已授权的本地 `cf auth login` 会话自动匹配账号即可。

## 五、给新会话 AI 的协作约定

当用户在后续对话中提出“**同步一下**”、“**发布上线**”、“**推送到 Git 和橙色云**”或类似指令时，接手会话的 AI 应当自动按本规范执行，无需反复向用户确认固定流程：

1. 根据实际改动文件自动判定 **A / B / C / D 改动级别**；
2. 若涉及 C 类或 B 类重要改动而尚未提升 `sw.js` 缓存号，主动递增 `CACHE_NAME`（及补全 `PRECACHE_URLS`）；
3. 依次跑完 `validate_course.mjs`、`npm run build`、`git status -s` / `git diff` 隐私红线审查；
4. 若 `cf auth whoami` 未登录或过期，启动 `cf auth login` 并给出一次性授权链接请用户点击一次后继续完成发布；
5. 提交并推送 `origin main` → 执行 `npm run deploy` → 实测线上关键 URL 返回 HTTP `200`；
6. 最后向用户简明汇报：Git Commit 编号、线上部署状态、抽检结果与变更文件列表。
